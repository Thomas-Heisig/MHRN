# CUDA PAN state inside the actual Builder

`neuron_backend=cuda_pan` selects FP64 membrane/spikes plus per-neuron PAN health, amplitude, energy, activity EMA, local-surprise information proxy, consolidation, hypervector and apoptosis decision. It requires `pan_adex_5d`. Both kernels share one driver context/module; separate buffers are reused through the run and cleaned on allocation/copy/launch/synchronization failure. Inputs and returned state reject NaN/Inf, invalid shape and invalid tick.

This remains a **hybrid non-canonical Playground backend**. Host code owns ordered population reduction, delayed feedback projection, apoptosis event bookkeeping, synapses/RNG, plasticity, growth, policy, body, sensors, actions, reward and Neural I/O. Per-tick transfers remain; no speedup, full CUDA-MHRN or canonical RuntimeController integration is claimed. GPU live sessions remain explicitly unsupported.

The Builder choice, export/import, run component table and D3 endpoint use the same selected backend. D3 captures full end-state PAN values and synaptic weights/delays/topology, in addition to sampled voltage, full spike digests, action/target/reward sequences and the entire body trajectory digest. D2 thresholds are 1e-12 for PAN/synaptic end state and 1e-4 for sampled membrane voltage. Missing PAN state or actual GPU ticks cannot pass the PAN stage.

Validation includes 129-neuron partial blocks, dimensions 5/10/32, activity/energy/consolidation, apoptosis and preserved dead state, injected resource failures, and three actual default 256-neuron/2048-edge/2000-tick RTX 3060 D3 pairs. All twelve initial tests passed locally, including six physical GPU cases (three dimension/lifecycle cases and three full D3 seeds). The broader backend selection passed 118 tests; opt-in hardware cases are separate. The RTX 3060 kernel uses 40 registers, 128 bytes stack and zero register spills. Full main CI remains a merge requirement. `cuda-ptxas` assembles the PAN-state kernel in the main CI.
